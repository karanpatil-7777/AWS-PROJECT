Architectural Explanations (Page 12 Viva Questions)

Key concepts evaluated during the project defense.

1 Why is the return route needed?

IP networking is bidirectional. When App-A sends a packet to App-B across the peering link, App-B's OS generates an ICMP Echo Reply. VPC B's route table must possess an explicit route matching 10.10.0.0/16 pointing to ewb-a-b-peer, otherwise the reply packet has no destination target and is dropped locally.

2 Why is App-B SSH source the bastion private IP?

OpenSSH ProxyJump terminates the laptop's TCP handshake at the Bastion. The Bastion daemon initiates a secondary TCP connection from its own network interface (10.10.1.10) to App-B (10.20.1.10:22). Therefore, App-B's ENI sees incoming traffic from the Bastion private IP, NOT the laptop public IP.

3 Why does Active peering not guarantee ping?

Active status only confirms the AWS control-plane handshake. For ICMP packets to succeed, three separate layers must be valid: (1) Route tables must route peer CIDRs to the peering ID, (2) Security groups must allow ICMP Echo Requests (Type 8, Code 0), and (3) Host OS kernel must permit ping replies.

4 Can VPC B use VPC A's internet gateway?

No. AWS VPC Peering is non-transitive and prohibits edge-to-edge routing. Traffic entering a VPC via a peering connection cannot exit through that VPC's Internet Gateway, NAT Gateway, or VPN. To provide VPC B egress, a local NAT Gateway or Transit Gateway is required.
